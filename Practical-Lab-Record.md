WEB APPLICATION SECURITY – PRACTICAL LAB RECORD

1. Aim

To understand web application security, identify common vulnerabilities, analyze potential risks and learn suitable remediation techniques in a controlled and authorized environment.

2. Objectives

- Understand web application security fundamentals.
- Study OWASP Top 10 vulnerabilities.
- Learn basic security testing concepts.
- Understand vulnerability analysis.
- Identify suitable security improvements.
- Prepare security documentation.

3. Requirements

- Android smartphone
- Internet connection
- GitHub account
- Chrome browser
- OWASP learning resources
- Authorized security training environment

4. Tools Used

Tool| Purpose
GitHub| Documentation and version control
Chrome| Accessing web applications
OWASP ZAP| Web security testing
OWASP Website| Security learning resources

5. Experiment 1 – Understanding HTTP Requests and Responses

Aim: To understand communication between a browser and a web server.

Theory:

HTTP stands for Hypertext Transfer Protocol. It allows browsers and servers to communicate.

An HTTP request is sent by a client, and the server returns an HTTP response.

Important HTTP Methods:

- GET – Retrieve information.
- POST – Submit information.
- PUT – Update information.
- DELETE – Remove information.

Result: Learned the basic concepts of HTTP communication.

6. Experiment 2 – OWASP Top 10 Analysis

Aim: To study common web application security vulnerabilities.

Procedure:

1. Open the official OWASP website.
2. Navigate to OWASP Top 10:2025.
3. Study the ten vulnerability categories.
4. Understand their possible impacts.
5. Record preventive measures.

Result: Studied the OWASP Top 10 security categories.

7. Experiment 3 – Understanding Authentication and Authorization

Aim: To understand how applications verify users and control access.

Theory:

Authentication verifies the identity of a user.

Authorization determines what resources and actions the user is permitted to access.

Security Measures:

- Strong passwords.
- Multi-factor authentication.
- Role-based access control.
- Secure session management.

Result: Understood the difference between authentication and authorization.

8. Experiment 4 – Input Validation and Injection Prevention

Aim: To understand safe handling of user input.

Theory:

Input validation ensures that information entered by users follows expected rules.

Prevention Techniques:

- Validate input on the server.
- Use parameterized queries.
- Avoid unsafe command construction.
- Apply appropriate output encoding.

Result: Understood basic input validation and injection prevention techniques.

9. Experiment 5 – Security Misconfiguration

Aim: To understand the risks of incorrect security settings.

Procedure:

1. Study common configuration mistakes.
2. Identify examples such as default credentials and unnecessary services.
3. Understand their possible impact.
4. Prepare security recommendations.

Result: Learned the importance of secure application configuration.

10. Experiment 6 – Vulnerability Reporting

Aim: To prepare a structured security vulnerability report.

Procedure:

1. Identify a potential security issue.
2. Describe the vulnerability.
3. Record its possible impact.
4. Suggest remediation methods.
5. Document the findings.

Result: Learned how to prepare a vulnerability report.

11. General Observations

- Web application security is important for protecting user data.
- Secure authentication reduces unauthorized access risks.
- Input validation helps prevent injection vulnerabilities.
- Proper configuration improves application security.
- Security documentation supports effective remediation.

12. Conclusion

This practical lab provided an introduction to web application security concepts and OWASP vulnerability analysis.

The exercises helped develop an understanding of HTTP communication, authentication, authorization, input validation, security misconfiguration and vulnerability reporting.
